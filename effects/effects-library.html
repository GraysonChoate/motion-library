SYS

Architecture

Read first. These change how everything after them is built.

Architecture is how motion is produced — not what it looks like.

What it actually is

The decisions underneath every effect: where the animation loop lives, what drives progress, how layout change is animated, what physical model your easing uses. None of it is visible. All of it is load-bearing.

Why it decides quality

This is the difference between a site running twenty effects at a steady 60fps and one that stutters on a two-year-old laptop. Every other group on this page depends on choices made here. Get it wrong and the fix is a rewrite, not a tweak.

What separates good from bad

The common failure is reaching for a library and adding an animation per component — twenty independent loops, each unaware of the others. Architecture-first means one loop, one source of scroll truth, and layout change animated through transforms.

Reach for it

Before writing a single line of scroll code. If you are already three components deep and adding a fourth requestAnimationFrame, stop and read this group.

Scroll — five ranges, zero JavaScript

SYS-01

Native CSS scroll timelines

browser-native, zero JS
What it does

Binds a keyframe animation directly to scroll position with animation-timeline: view(). No JS, no rAF, no IntersectionObserver — and it runs off the main thread, so it physically cannot jank when your JS is busy.

When to use it

Reach for this before writing any scroll JS. It would replace a large share of the code in this library. Baseline in Chrome, Edge and Safari; Firefox behind a flag; wrap in @supports and it degrades to no animation.

Watch the overflow gotcha in the code below — an overflow:hidden ancestor silently freezes it, which cost an hour of this library's build.

Code
/* the entire technique — no JavaScript at all */
@supports (animation-timeline: view()) {
  .bar {
    animation: grow linear both;
    animation-timeline: view();              /* progress = element through viewport */
    animation-range: entry 10% cover 55%;    /* when it starts and finishes */
  }
}
@keyframes grow { from { transform: scaleX(0) } to { transform: scaleX(1) } }

/* other timelines available:
   scroll()          — progress of the nearest scroll container
   view()            — progress of THIS element through the viewport
   animation-range   — entry / exit / cover / contain, each 0-100%          */

⚠ THE GOTCHA THAT COSTS AN HOUR — found by auditing this very page
/* ANY ancestor with overflow:hidden becomes a SCROLL CONTAINER, and view()
   resolves against the nearest scrollport. If that box never scrolls, your
   progress freezes at whatever value it happened to hold — no error, no
   warning, nothing in devtools. It just sits there.

   You must clear the WHOLE ancestor chain, not just the parent. On this page
   three separate ancestors were doing it, including the one nobody suspects: */

body   { overflow-x: clip; }   /* NOT hidden. Per spec, overflow-x:hidden
                                   forces overflow-y to auto — so the single
                                   most common line in any stylesheet quietly
                                   turns <body> into a scroll container.     */
.card  { overflow: clip; }     /* every clipping wrapper in between      */
.stage { overflow: clip; }

/* overflow:clip clips identically and creates no scrollport.
   Baseline everywhere that supports scroll timelines, so there is no reason
   to use hidden on an ancestor of a scroll-driven animation.               */

Layout changes, animated by transform only

SYS-02

FLIP layout animation

First, Last, Invert, Play
What it does

Measure an element's position before a layout change, apply the change, measure again, then apply an inverse transform and release it. The browser animates a transform while the real layout is already final.

When to use it

Any time layout itself changes — reordering, filtering, expanding, adding. Animating left/width directly forces layout every frame and will never hit 60fps. This is the most important technique in the library and the one fewest people know.

Code
// 1. FIRST — measure before the change
const first = new Map();
items.forEach(el => first.set(el, el.getBoundingClientRect()));

// 2. mutate the DOM however you like — reorder, filter, resize
shuffle(container);

// 3. LAST + INVERT — measure again, apply the inverse offset
items.forEach(el => {
  const a = first.get(el), b = el.getBoundingClientRect();
  const dx = a.left - b.left, dy = a.top - b.top;
  if (!dx && !dy) return;
  el.style.transition = 'none';
  el.style.transform  = `translate(${dx}px, ${dy}px)`;   // looks unmoved
});

// 4. PLAY — next frame, release to zero
requestAnimationFrame(() => {
  items.forEach(el => {
    el.style.transition = 'transform .55s cubic-bezier(.2,.8,.2,1)';
    el.style.transform  = '';
  });
});
// reads are batched before writes — interleaving them forces sync layout

SYS-03

Spring physics vs easing

velocity-aware motion
What it does

An easing curve has a fixed duration and ignores what the element was already doing. A spring integrates position and velocity every frame, so an interruption carries momentum through instead of restarting.

When to use it

Anything a user can interrupt — drags, toggles, anything re-triggered mid-flight. It's the reason native app motion feels different from web motion. Tune with stiffness and damping, not duration.

Code
// spring: no duration — it settles when it settles
const K = 0.10;   // stiffness — how hard it pulls toward target
const D = 0.72;   // damping   — how fast it loses energy (1 = none)

let pos = 0, vel = 0, target = 0;

function frame(){
  const force = (target - pos) * K;
  vel = (vel + force) * D;      // accumulate, then damp
  pos += vel;
  el.style.transform = `translateX(${pos}px)`;
}
// D < 0.7  overdamped, no overshoot
// D ≈ 0.75 one soft overshoot — usually what you want
// D > 0.85 visibly bouncy, use sparingly

SYS-04

View Transitions

browser-native morphing
What it does

Give two elements the same view-transition-name across a DOM change and the browser morphs one into the other — position, size and crossfade — automatically. Wrap the change in startViewTransition and that is the entire implementation.

When to use it

Expanding a card into a detail view, filtering a list, or full page navigation. This is how you get app-like transitions with no framework. Names must be unique at any moment, so assign them to the participating elements only, then clear them.

Code
// same-document: wrap the DOM change, that is all
document.startViewTransition(() => {
  grid.hidden = true;
  detail.hidden = false;
});

/* the browser matches elements sharing a name and tweens between them */

SYS-05

Speculation Rules

prefetch and prerender on intent
What it does

A JSON block telling the browser which links to prefetch or fully prerender before the user clicks. With eagerness: "moderate" it fires on hover or touchstart, so by the time the click lands the next page is already rendered.

When to use it

Any multi-page site. Paired with cross-document View Transitions it produces navigation that feels like a single-page app with none of the machinery. Prerender aggressively only on safe GET pages — it executes the page's scripts, so never prerender anything that mutates state.

Code
<script type="speculationrules">
{
  "prerender": [{
    "where": { "href_matches": "/*" },
    "eagerness": "moderate"        // fires on hover / touchstart
  }],
  "prefetch": [{
    "where": { "href_matches": "/*" },
    "eagerness": "conservative"    // fires on pointerdown
  }]
}
</script>

/* eagerness scale:
     immediate     — as soon as the rule is parsed
     eager         — as soon as the link is even slightly likely
     moderate      — on hover ~200ms, or touchstart      <- the useful one
     conservative  — on pointerdown, just before the click             */

GL

Rendered

The GPU tier. Where the award-circuit work lives.

Rendered means the pixels are computed by the GPU, per frame, from a program you wrote.

What it actually is

A fragment shader runs once per pixel, every frame — a few million tiny programs in parallel. Nothing is a DOM element, nothing has a layout, and cost scales with screen area rather than element count.

Why it decides quality

Everything else in this library manipulates boxes. This group manipulates light, matter and space directly — refraction, fluid, volumetric depth, infinite procedural geometry. It is the difference between a site that looks designed and one that looks impossible.

The danger

It is a different medium with different failure modes: no devtools inspector, silent black screens, wildly different mobile GPUs, and battery cost. A shader you cannot debug on a client's laptop is worse than no shader. Always ship a static fallback.

The dependency exception

Everything here is raw WebGL2 — still zero dependencies. Real production work usually means Three.js. This is the one group permitted a library, and that permission does not extend anywhere else.

GL-01

Raymarched SDF field

fragment shader, zero geometry
What it does

Geometry defined as a distance function rather than vertices. Each pixel marches a ray forward until it hits a surface, so the shape is math — infinitely detailed, zero polygons, zero assets.

When to use it

Backgrounds that need to feel deep and endless. Cost is per pixel, not per object, so a hundred shapes cost the same as one. Watch resolution on mobile — this is the technique most likely to melt a phone if you render at full DPR.

Code
// distance from point p to the nearest surface in the scene
float map(vec3 p){
  p.xz = mod(p.xz + 2.0, 4.0) - 2.0;      // domain repetition = infinite grid
  float sphere = length(p) - 0.9;
  float ground = p.y + 1.2;
  return min(sphere, ground);               // min() = union of shapes
}

// march the ray until we are close enough to call it a hit
float march(vec3 ro, vec3 rd){
  float t = 0.0;
  for (int i = 0; i < 72; i++){            // step count = quality vs cost
    float d = map(ro + rd * t);
    if (d < 0.001 || t > 40.0) break;
    t += d;                               // safe to step exactly d — nothing is closer
  }
  return t;
}

// normal from the gradient of the distance field
vec3 normal(vec3 p){
  vec2 e = vec2(0.001, 0.0);
  return normalize(vec3(map(p+e.xyy)-map(p-e.xyy),
                        map(p+e.yxy)-map(p-e.yxy),
                        map(p+e.yyx)-map(p-e.yyx)));
}

GL-02

Dispersion glass

index-of-refraction shader
What it does

Light bent through a surface, with red, green and blue refracted at slightly different angles — which is what actually produces the rainbow fringing at the edges of real glass. Not backdrop-filter; a physical model.

When to use it

Hero objects, product stand-ins, anything that should read as a physical material. The chromatic split is the entire tell — refract all three channels identically and it just looks like a blurry circle.

Code
// sample the background three times, one per channel, at different IOR
float ior = 1.45;
vec3 refR = refract(rd, n, 1.0/(ior - 0.014));   // red bends least
vec3 refG = refract(rd, n, 1.0/ior);
vec3 refB = refract(rd, n, 1.0/(ior + 0.014));   // blue bends most

vec3 col = vec3(
  sampleBackground(refR).r,
  sampleBackground(refG).g,
  sampleBackground(refB).b
);

// Fresnel — glass is mirror-like at glancing angles, clear head-on
float f = pow(1.0 - max(dot(n, -rd), 0.0), 5.0);
col = mix(col, reflection, f * 0.9);

GL-03

Displacement transition

two textures, one noise map
What it does

Two images blended by a noise texture that pushes UVs apart as the mix progresses. Instead of a crossfade, the first image appears to melt or tear into the second.

When to use it

The standard portfolio hero transition. The character comes entirely from the noise map — smooth noise gives liquid, ridged noise gives shattering, directional noise gives a wipe. Same twelve lines of shader either way.

Code
uniform float uProg;      // 0 → 1

float n = noise(uv * 3.0);                 // the displacement map
float amt = 0.42;                          // how far UVs get pushed

// each texture is distorted in the OPPOSITE direction
vec2 uvA = uv + vec2(n - 0.5) * amt *      uProg;
vec2 uvB = uv - vec2(n - 0.5) * amt * (1.0-uProg);

vec4 a = texture(texA, uvA);
vec4 b = texture(texB, uvB);

// sharpen the blend so it tears rather than dissolves
float m = smoothstep(n - 0.15, n + 0.15, uProg);
outColor = mix(a, b, m);

GL-04

Fluid cursor

ping-pong advection
What it does

A real velocity field on the GPU. The pointer injects force and dye; every frame the field is advected — each pixel samples where it came from — then dissipated. Two framebuffers swap roles each frame, which is how GPU simulations hold state.

When to use it

One hero moment, never twice on a page. This is the most expensive thing in the library and the most impressive. Ping-pong buffers are the general pattern for any GPU simulation — fluid, particles, cellular automata all use it.

Code
// the whole idea: you cannot read and write the same texture,
// so you keep two and swap them every frame
let read = fboA, write = fboB;

function step(){
  // ADVECT — trace backwards to find where this pixel's value came from
  bind(write);
  useShader(advect, {
    uSrc: read.texture,
    uVel: read.texture,
    uDissipation: 0.982      // <1 or the field never settles
  });
  drawQuad();

  [read, write] = [write, read];   // PING-PONG — the swap is the trick
}

// advect.frag — sample backwards along the velocity field
vec2 back = uv - texture(uVel, uv).xy * uDt;
outColor = texture(uSrc, back) * uDissipation;

GL-05

GPGPU particles

positions stored in a texture
What it does

Particle positions live in a floating-point texture, not in JavaScript. A shader updates all of them in one draw call, then the vertex shader reads that texture to place points. The CPU never touches a particle.

When to use it

Any particle count past a few thousand. Our canvas field caps around 150 before it costs frames; this runs tens of thousands at the same price, because the work happens in parallel on the GPU and never crosses the CPU boundary.

Code
// state lives in a texture: RGBA = x, y, vx, vy — one texel per particle
// UPDATE pass — runs once for ALL particles
vec4 s = texture(uState, uv);
vec2 pos = s.xy, vel = s.zw;

vec2 toM = uMouse - pos;
float d  = max(length(toM), 0.02);
vel += normalize(toM) * 0.0009 / (d*d);   // inverse-square attraction
vel *= 0.982;                             // drag
pos += vel;

o = vec4(pos, vel);                      // write the new state

// RENDER pass — vertex shader READS that texture to place each point
vec4 s = texelFetch(uState, ivec2(idx % W, idx / W), 0);
gl_Position  = vec4(s.xy, 0.0, 1.0);
gl_PointSize = 2.0 + length(s.zw) * 40.0;

// ping-pong again — you cannot read and write the same texture */

GL-06

Post-processing stack

render to texture, then treat it
What it does

The scene renders into a framebuffer instead of the screen, then that image passes through treatment shaders — bright-pass, blur, chromatic aberration, vignette, grain — before being drawn. Exactly how a film grade works.

When to use it

This is the single biggest difference between WebGL that looks like a demo and WebGL that looks cinematic. Bloom is what sells emissive materials; nothing in the raw render glows. Keep the bright-pass threshold high or the whole frame smears.

Code
// 1. render the scene into a texture instead of the screen
gl.bindFramebuffer(gl.FRAMEBUFFER, sceneFBO);
drawScene();

// 2. bright-pass — keep only what should glow
vec3 c = texture(uScene, uv).rgb;
float lum = dot(c, vec3(0.2126, 0.7152, 0.0722));
o = vec4(c * step(0.72, lum), 1.0);      // threshold — high, or everything smears

// 3. blur that, then composite back over the original
vec3 col = scene + bloom * 0.85;

// 4. chromatic aberration — offset channels radially from centre
vec2 dir = (uv - 0.5);
float k = 0.004 * dot(dir, dir) * 4.0;   // stronger toward the edges
col.r = texture(uScene, uv + dir*k).r;
col.b = texture(uScene, uv - dir*k).b;

// 5. vignette and grain last — always last, or the bloom eats them
col *= 1.0 - dot(dir,dir)*0.85;
col += (hash(uv*uTime) - 0.5) * 0.035;

GL-07

Mesh distortion on scroll

vertex displacement
What it does

A subdivided plane whose vertices are displaced in the vertex shader by scroll velocity. The surface bulges and curves as you scroll and settles when you stop, so the page has a physical skin rather than flat rectangles.

When to use it

Image grids and full-bleed media. Subtlety is everything — a few percent of displacement reads as material, more reads as a funhouse mirror. It needs real geometry, so this is the one technique here that cannot be done with a single full-screen quad.

Code
// vertex shader — displace the grid, do not touch the fragment
uniform float uVel;      // smoothed scroll velocity, clamped

vec3 pos = position;

// curve the sheet: strongest at the centre, zero at the edges
float edge = 1.0 - abs(pos.x);
pos.z += sin(pos.x * 3.14159) * uVel * 0.35;
pos.y += edge * uVel * 0.12;

// a travelling ripple so the distortion is not a rigid bend
pos.z += sin(pos.y * 6.0 - uTime * 2.0) * uVel * 0.06;

gl_Position = uProj * vec4(pos, 1.0);

// grid resolution decides smoothness: 40x40 is plenty for a bend,
// 4x4 will show faceting the moment anything curves            */
DEP

Depth

Turning flat surfaces into space you move through, rather than pictures you scroll past.

Depth is making a flat plane read as space you could walk into.

What it actually is

Relative motion between layers, occlusion, perspective, and focus falling off with distance. Four cues the eye trusts automatically, because they are how real lenses and real rooms behave.

Why it decides quality

The largest single contributor to a site feeling crafted rather than assembled. When someone says a site feels premium without being able to say why, they are almost always responding to depth.

The mistake almost everyone makes

Depth is not arrival. Elements fading up as you scroll is not dimension — it is a queue. Real depth needs planes moving at different rates and silhouettes that cross each other and blur on the nearest layer. Two out of three still reads flat.

Reach for it

Heroes, product ranges, anything built from still images. It is the honest answer when a client has beautiful photography and a site that wastes it.

DEP-01

Multi-plane parallax

pointer + scroll parallax
What it does

Six planes with real silhouettes — back wall, lit aperture, side columns, lintel, floor wash, blurred foreground mass. Each translates by depth × pointer and depth × scroll; the foreground swings ~20× further than the wall. Hit Show planes to see the separation.

When to use it

Any hero built from stills — the highest return-on-effort technique here. Two rules learned the hard way: planes need edges that cross each other (gradient washes read as one flat image no matter how you move them), and the nearest plane must be blurred and travel hardest, because that's how real lenses behave.

Code
const planes = [...stage.querySelectorAll('[data-depth]')];
let px = 0, py = 0;

function frame(){
  px = lerp(px, pointer.inside ? pointer.nx : 0, 0.07);   // nx,ny = -0.5 … 0.5
  py = lerp(py, pointer.inside ? pointer.ny : 0, 0.07);

  const r = stage.getBoundingClientRect();
  const s = ((innerHeight - r.top) / (innerHeight + r.height) - .5) * 2;   // -1 … 1

  for (const p of planes){
    const d = +p.dataset.depth;                  // 0.05 … 1.00
    const x = px * -150 * d;                     // was -60 — far too timid
    const y = py * -95  * d + s * 150 * d;
    const rot = px * 2.2 * d;                    // rotation sells the swing
    p.style.transform =
      `translate3d(${x}px,${y}px,0) rotate(${rot}deg) scale(${1 + d * .07})`;
  }
}
// three things make parallax READ, and all three are required:
//  1. silhouettes that occlude each other (pillars crossing the arch)
//  2. enough travel — 150px on the near plane, not 40
//  3. blur on the nearest plane, so it behaves like a lens not a sticker

DEP-02

Pointer-tilted panel

pointer-driven 3D transform
What it does

A parent holds perspective; the child rotates on X and Y toward the pointer and translates slightly with it. The card reads as a physical plate catching light rather than a div.

When to use it

Pull-quotes, story panels, a single product card. Keep rotation under 6° — past that it stops reading as a tilt and starts reading as a gimmick. Never tilt a block of running text a reader has to follow.

Code
// parent needs perspective; card needs preserve-3d
.wrap { perspective: 1100px; }
.card { transform-style: preserve-3d; will-change: transform; }

let rx = 0, ry = 0, trx = 0, try_ = 0;
stage.addEventListener('pointermove', e => {
  const r = card.getBoundingClientRect();
  const mx = (e.clientX - (r.left + r.width/2))  / (r.width/2);
  const my = (e.clientY - (r.top  + r.height/2)) / (r.height/2);
  try_ =  my * -5;   // invert Y: cursor above ⇒ top tips away
  trx =  mx * 6;
});

  rx += (trx - rx) * .09;
  ry += (try_ - ry) * .09;
  card.style.transform =
    `rotateY(${rx}deg) rotateX(${ry}deg) translate3d(${rx*1.6}px,${ry*1.2}px,0)`;
}
// the small translate is what sells it — pure rotation feels hinged, not floating

DEP-03

Focus falloff carousel

depth via blur, not position
What it does

Pointer position drives a virtual focal plane. Cards near it are sharp, full-opacity and forward; cards away from it blur and recede — a lens behaviour, not a layout behaviour.

When to use it

Product ranges where one item should dominate without a click. Depth-of-field is the cue the eye trusts most for distance, and it's cheaper than parallax because nothing needs to move far.

Code
const cards = [...stage.querySelectorAll('.card')];
let focus = 1, target = 1;                        // which card is "in focus"

stage.addEventListener('pointermove', e => {
  const r = stage.getBoundingClientRect();
  target = ((e.clientX - r.left) / r.width) * (cards.length - 1);
});

function frame(){
  focus += (target - focus) * .08;
  cards.forEach((c, i) => {
    const d = Math.abs(i - focus);                // distance from focal plane
    c.style.transform =
      `translateX(${(i - focus) * 62}%) scale(${1 - d * .12}) translateZ(0)`;
    c.style.filter  = `blur(${d * 5}px) brightness(${1 - d * .3})`;
    c.style.opacity = String(1 - d * .34);
    c.style.zIndex  = String(100 - Math.round(d * 10));
  });
}
// blur + brightness + scale together; any one alone reads flat
REA

Reactivity

The page answering the pointer. This is the category video physically cannot compete in.

Reactivity is the page answering you inside the same frame.

What it actually is

Reading pointer position, velocity or proximity and responding immediately — light that follows the cursor, controls that lean toward it, particles that scatter and settle.

Why it decides quality

This is the one category video physically cannot compete in. A film plays back identically for everyone; a reactive page acknowledges that a specific person is present. That acknowledgement is the difference between a site that feels alive and one that is merely well-produced.

The danger

Reactivity is addictive and trivially overdone. If everything responds, nothing means anything and the page becomes noise that fights the content. One, maybe two reactive moments per page. Everything else stays still.

Reach for it

The hero, and the single most important control. It also needs a touch story — every technique here does nothing on a phone unless you design the fallback.

Sweep cursor through the field

REA-01

Particle field with pointer wake

canvas particle system
What it does

Canvas particles drift upward with per-particle wander and a slow opacity flicker. The pointer applies a falloff repulsion, so sweeping through leaves a wake that settles — the page registers that you were there.

When to use it

Ambient life behind a hero. Scale count to viewport area, cap it, and never run it off screen. Additive blending gives depth where particles overlap; keep saturation low or it reads as a screensaver.

Code
const P = [], N = Math.min(140, Math.floor(w * h / 9000));   // area-scaled, capped
for (let i = 0; i < N; i++) P.push({
  x: Math.random()*w, y: Math.random()*h,
  vx: (Math.random()-.5)*.25, vy: -(.18 + Math.random()*.55), // embers rise
  r: Math.random()*1.7 + .5, life: Math.random(),
  hue: 38 + Math.random()*14                                  // brass → honey-gold
});

function frame(){
  ctx.clearRect(0,0,w,h);
  ctx.globalCompositeOperation = 'lighter';        // additive = glow
  for (const p of P){
    p.x += p.vx; p.y += p.vy;
    p.vx += (Math.random()-.5) * .02;              // thermal wander

    if (pointer.inside){                             // pointer wake
      const dx = p.x - pointer.x, dy = p.y - pointer.y;
      const d2 = dx*dx + dy*dy;
      if (d2 < 120*120){
        const f = (1 - Math.sqrt(d2)/120) * .9;    // linear falloff
        p.vx += (dx/(Math.sqrt(d2)||1)) * f;
        p.vy += (dy/(Math.sqrt(d2)||1)) * f;
      }
    }

What it does

const GLYPHS = 'ABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789#%&@$/\\|=+-';

function scramble(el, text, ms = 1400){
  el.setAttribute('aria-label', text);            // the real string, always
  const start = performance.now();

  (function step(now){
    const p = Math.min(1, (now - start) / ms);
    const locked = Math.floor(p * text.length);   // resolve left to right

// piecewise interpolation across multi-stop ranges (Framer useTransform, vanilla)
function mapStops(v, inS, outS){
  if (v <= inS[0]) return outS[0];
  if (v >= inS[inS.length-1]) return outS[outS.length-1];
  for (let i = 0; i < inS.length-1; i++){
    if (v >= inS[i] && v <= inS[i+1]){
      const t = (v - inS[i]) / (inS[i+1] - inS[i]);
      return outS[i] + (outS[i+1] - outS[i]) * t;
    }
  }
}

  [0.00, 0.06, 0.26, 0.33],
  [0.34, 0.40, 0.60, 0.67],
  [0.68, 0.74, 0.94, 1.00],
];

  set.style.filter  = `blur(${mapStops(p, w, [15,0,0,15])}px)`;

AMB

Ambient

Atmosphere and idle life. The quietest group — everything here should be noticed only in its absence.

Ambient is continuous atmosphere that never asks for attention.

What it actually is

Low-amplitude, always-running texture: film grain, slow drift, a barely-moving noise field. Nothing here is triggered, and nothing here is a moment.

Why it decides quality

It is what makes a page feel like a surface rather than a screen. Large flat colour fields band and look digital; grain kills banding and gives the eye something to read as material. It is also the cheapest way to make a dark design feel photographic instead of empty.

The rule

It should be noticed only in its absence. If a visitor can describe the ambient layer, it is too strong. The correct test is to switch it off — the page should feel slightly worse without anyone being able to say why.

Reach for it

Large flat areas, dark designs prone to gradient banding, and any page that feels sterile without you being able to name what is missing.

What it does

AMB-04

The gauge

Measure before you cut

Research is the whole job. Direction, palette, copy and motion are all derivatives of this phase. Get it wrong and you produce something confident, polished, and about a company that doesn't exist.

Seven phases, in order. Each has a gate — don't start the next until it passes. Most of the damage in the first run came from skipping ahead.

The workflow

01
Access check · 10 min

One probe per source. Write down what you reached and what you didn't.

GATE — a written statement of what you could not reach.

02
First-party scrape · 30 min

A small business's own site almost never fights scrapers. Pull the homepage, about, story and menu pages. Extract platform, fonts, hex frequency, nav IA, image assets.

GATE — HTML on disk, 200 status, non-trivial byte count.

03
Measure · 20 min

Hex frequency in their HTML ranks brand importance. ImageMagick on their own photography gives the photographic palette and mean brightness — which is a design directive, not a mood.

GATE — a palette table where every hex traces to a measured source.

04
Mine words & structure · 30 min

Hunt a latent narrative structure, a tagline they own, their best sentence, a naming system, a latent interaction, and trademarks. Never invent an arc before checking for theirs.

GATE — verbatim quotes with the page each came from.

05
Diagnosis · 15 min

List what the homepage leads with. List their strongest owned material. The gap is the thesis.

GATE — one sentence. If it needs a paragraph, you don't have it yet.

06
Direction · 45 min

Constraints first, all from measured data. Then one direction and one signature interaction. Ban imported mood — steal a reference's mechanics, reject its genre.

GATE — written direction, zero code, every claim traceable.

07
Build · varies

Effects tab for the parts, Standards tab for the floor.

Verify — the part that gets skipped

Two-source rule

Anything load-bearing — a fact that changes the design if it's wrong — needs two independent sources. Their About page and their homepage are one source: the company.

Tier audit

Walk every field and downgrade ruthlessly. Claims drift upward through repetition — the palette guess was being treated as measured within two messages purely from being restated.

Falsification — three attacks

  1. Palette attack. If I'm wrong about the dominant colour, what would I expect instead? Go look for it on a page you haven't scraped.
  2. Story attack. Am I building on what they emphasise, or what I find charming? If it appears once in a footer, it's your preference.
  3. Customer attack. Does my read contradict the reviews? If they disagree, the reviews win.

Customer voice — do not skip

Read 20+ reviews and the comments under their top posts. You are hunting one thing: the gap between how the business describes itself and how customers describe it.

The word customers use that the brand never does is usually your headline.

Definition of done

  • Every card field filled or marked NOT FOUND
  • Every fact carries a tier and a source URL
  • Every load-bearing fact has two sources, or a SINGLE-SOURCE flag
  • Tier audit done; nothing below C entering the direction
  • All three falsification attacks attempted and recorded
  • Customer-voice pass done; the gap written down
  • Diagnosis is one sentence

The classifier

Two questions place any business

Businesses don't cluster by category. A yoga studio and a barbershop are the same design problem — book a slot with a person in a space. A café and a taco stand are the same problem — come here, now.

So there are two axes. Pattern decides structure — sections, order, money action, required components. Register decides treatment — palette, type, density, which effects are allowed.

8 patterns × 6 registers = 48 briefs from 14 lookups, and it covers business types nobody wrote down. A pet groomer is A × Community. A crossfit box is C × Raw. A wine bar is B × Craft.

The furniture

Everything that isn't motion

A mockup is roughly 80% structure and 20% motion. This is the 80%: tokens, layout archetypes, the utility components each business type actually requires, photo treatments for imagery that arrives imperfect, and the edge language that reads as expensive in 2026.

The AI assembles from here. It should never invent a spacing value, a type size, or a component that already exists below. Inventing structure is where the time goes and where quality becomes a coin flip.

KIT 02

Layout archetypes

Pick one hero and one section rhythm. Never design a layout from scratch — that is where the twenty minutes goes.

Hero archetypes — pick exactly one

Full-bleedOne strong photograph, type over the lower third. Needs a genuinely good image — if the photo is weak this archetype fails hardest.
Editorial splitType left, image right. The safest strong choice and the best default when photography is only average.
Type-firstEnormous headline, no hero image at all. The correct answer when their photography is unusable — and it reads as confident rather than as a gap.
BentoTiled grid of unequal cells. Dominant 2026 pattern and it ships. Ideal when they have many mediocre photos rather than one good one.
Centred classicSymmetrical, calm, low risk. Right for clinical and luxury registers where restraint is the signal.

Section rhythm

After the hero, alternate wide → narrow → wide. Never run three full-width sections in a row — the page stops having a pulse and starts feeling like a scroll. Content column caps at 1120px; prose caps at 68ch regardless of container.

Six to eight sections total. Fewer reads thin, more reads like a template. Every section earns its place by answering one question the visitor actually has.

KIT 04

Photo treatment

Client photography arrives inconsistent. Treatment is what turns a mixed bag into a set.

Four recipes, in order of how much they rescue

UntreatedMixed white balance, no relationship to any other image on the page.
GradeContrast up, saturation down, soft-light gradient in brand colours. Keeps it photographic. Use first.
DuotoneDesaturate, then map shadows and highlights to two brand colours. Forces any set into one palette. Use when photos clash badly.
Gradient washDarken the lower third so type sits on it. Not a rescue — a legibility requirement for full-bleed heroes.

The recipe. Desaturate → fix levels and contrast → gradient-map shadows to the brand's dark and highlights to its light → set the map to soft-light or colour → pull opacity back until it stops looking like a filter.

Crop discipline. Three ratios only — 16:9 wide, 4:3 standard, 3:4 portrait. Mixed arbitrary ratios are the second-biggest tell of an amateur page after inconsistent spacing.

The rejection rule. Under 1200px wide, visibly blurry, or watermarked → don't rescue it, drop it and change archetype. Type-first hero exists precisely for this case. And generated imagery must never depict the actual business — no invented storefronts, no invented staff. Abstract, textural or product-adjacent only.

KIT 05

Edge language

How things are separated. Small decision, disproportionate effect on perceived cost.

1px hairline
blur shadow
inset highlight
tonal step

Default to the hairline. 1px at 15–20% opacity, 2px radius. 2026 premium reads as engineered precision — sharp geometry and thin rules. The soft blurred shadow with a 16px radius is the most dated thing you can put on a page; it reads as 2019 and it reads as a template.

Use tonal steps — a surface one shade lighter than its ground — where a border would be too much. Use inset highlights only on interactive elements, where the 1px light line along the top edge reads as a real physical control.

KIT 06

Texture

What stops large flat areas reading as unfinished.

Grain — AMB-01, at 3–5% opacity, mix-blend-mode: overlay. Kills gradient banding and makes a flat field read as a surface. Nearly always worth it on a dark page.

Gradient mesh — AMB-02, blurred blobs behind content. Fills empty regions without adding content. Keep blur above 40px or the blobs become visible shapes.

Hairline grid — a 1px rule every 96px at 4% opacity. Almost invisible, but it makes the layout feel engineered rather than floated. Cheapest premium signal in the kit.

Never: visible noise PNGs, paper textures at high opacity, gradient meshes bright enough to read as blobs, or texture on top of body text.

The tolerances

The floor you don't go below

Ordered by when you hit it: while building, then before shipping.

1 · Demo values are not ship values

Everything in the Effects tab is tuned so the effect is obvious at a glance. Production wants the opposite: the page feels alive and the reader never notices the mechanism. Ship roughly 40–50% of demo values.

If a colleague can describe what the animation did, it's too strong.

The four that most need dialling back: depth travel, velocity skew, particle repulsion, magnet pull. Reveals and staggers were already tuned for production — ship those as-is.

2 · One loop, gated

One requestAnimationFrame for the whole page. Every animated section gated by an IntersectionObserver so nothing off screen computes. A dozen private loops will idle a page at 100% CPU.

Anything added to Effects must register through the shared loop. A technique that ships its own rAF doesn't go in.

3 · Performance

  • Animate transform and opacity only where possible — they're compositor-only. Animating top, width or height forces layout every frame.
  • will-change on anything animating mask-image, clip-path or filter.
  • Separate reads from writes. Batch every getBoundingClientRect before any style write. Interleaving forces synchronous layout each frame — the actual cause of most "why is my scroll animation janky."
  • Passive listeners on scroll, wheel and touchmove.
  • Clamp inputs before mapping, never outputs after.
  • content-visibility: auto on long offscreen sections.

4 · Accessibility

  • prefers-reduced-motion is a designed state, not a kill switch. Turning effects off leaves a dead page. Design the deliberate static composition. This is also the honest answer for vestibular disorders, which large-field parallax genuinely triggers.
  • aria-label on any split text. Splitting a headline into spans destroys the accessible string — label the parent, aria-hidden the pieces.
  • Visible :focus-visible on every control.
  • Real controls. Buttons are <button>. State is announced. A styled div is not a control.
  • Contrast holds during motion — text mid-blur still has to be readable at every frame it's legible in.

5 · Mobile

  • Re-check axis-dependent effects. A horizontal wipe on a one-column phone layout reveals nothing.
  • Pointer effects need a touch story. Tilt, magnetism and cursor-followers do nothing on a phone — provide a device-orientation equivalent or design the static state.
  • Halve particle counts and blur radii. Blur is expensive on mobile GPUs.

6 · Typography

  • Font loading must not shift layout — font-display: swap plus size-adjust and metric overrides on the fallback.
  • Running text near 65 characters; text-wrap: balance on headings.
  • tabular-nums wherever digits line up in columns.

7 · Concept work

  • Label it in the page — visible and persistent.
  • Invent nothing. No prices, reviews, testimonials, credentials or links you haven't verified.
  • Carry the ® on registered marks.
  • Never imply a relationship that doesn't exist.

Before anything ships

  • Ship values, not demo values
  • One rAF loop, all sections gated
  • Reduced-motion has a designed state, not a blank one
  • Split text carries aria-label
  • Every control keyboard-operable with visible focus
  • Mobile: axis effects re-checked, pointer effects have a fallback
  • No layout thrash — reads batched before writes
  • Fonts don't shift layout on load
