Fourteen ways to make a
flat page feel lit from within

A working bench of scroll and pointer techniques, pulled apart from five reference builds and rebuilt with zero video and zero image assets. Every demo below is live — move your cursor into it, scroll through it, drag it. The code is underneath each one.

Palette and temperature are measured from Summer Moon Coffee's own site and store photography, so this doubles as look-dev: gold #E3B245, ember #A45126, slate #6D7B9D, at the 31–50% screen brightness their rooms actually measure.

Deps none Assets zero Loop one shared rAF Reduced-motion every demo

Depth beats motion

Things arriving on screen is not dimension. Dimension is parallax between planes, focus falling off with distance, and light that moves independently of the object it lands on.

Input is the material

Video can't answer the cursor. Every technique here reads pointer or scroll and responds inside the same frame, which is the entire difference between alive and playing back.

One loop, gated

Fourteen effects, a single requestAnimationFrame, and nothing computed for a stage that's off screen. Fourteen private loops is how a page like this dies on a laptop.

Motion carries meaning

Copy moves to show hierarchy, sequence, or consequence. If a reader can't tell why a word moved, the movement was decoration and it costs legibility.

DEP-01

Multi-plane parallax

from Urban Jungle mouse-parallax
What it does

Five planes with real silhouettes — wall, roaster mouth, brick pillars, coal bed, blurred foreground embers. Each translates by depth × pointer and depth × scroll; the foreground swings ~20× further than the wall. Hit Show planes to see the separation.

When to use it

Any hero built from stills — the highest return-on-effort technique here. Two rules learned the hard way: planes need edges that cross each other (gradient washes read as one flat image no matter how you move them), and the nearest plane must be blurred and travel hardest, because that's how real lenses behave.

Code
const planes = [...stage.querySelectorAll('[data-depth]')];
let px = 0, py = 0;

function frame(){
  px = lerp(px, pointer.inside ? pointer.nx : 0, 0.07);   // nx,ny = -0.5 … 0.5
  py = lerp(py, pointer.inside ? pointer.ny : 0, 0.07);

  const r = stage.getBoundingClientRect();
  const s = ((innerHeight - r.top) / (innerHeight + r.height) - .5) * 2;   // -1 … 1

  for (const p of planes){
    const d = +p.dataset.depth;                  // 0.05 … 1.00
    const x = px * -150 * d;                     // was -60 — far too timid
    const y = py * -95  * d + s * 150 * d;
    const rot = px * 2.2 * d;                    // rotation sells the swing
    p.style.transform =
      `translate3d(${x}px,${y}px,0) rotate(${rot}deg) scale(${1 + d * .07})`;
  }
}
// three things make parallax READ, and all three are required:
//  1. silhouettes that occlude each other (pillars crossing the arch)
//  2. enough travel — 150px on the near plane, not 40
//  3. blur on the nearest plane, so it behaves like a lens not a sticker

DEP-02

Pointer-tilted panel

from Urban Jungle GlassPanel
What it does

A parent holds perspective; the child rotates on X and Y toward the pointer and translates slightly with it. The card reads as a physical plate catching light rather than a div.

When to use it

Pull-quotes, story panels, a single product card. Keep rotation under 6° — past that it stops reading as a tilt and starts reading as a gimmick. Never tilt a block of running text a reader has to follow.

Code
// parent needs perspective; card needs preserve-3d
.wrap { perspective: 1100px; }
.card { transform-style: preserve-3d; will-change: transform; }

let rx = 0, ry = 0, trx = 0, try_ = 0;
stage.addEventListener('pointermove', e => {
  const r = card.getBoundingClientRect();
  const mx = (e.clientX - (r.left + r.width/2))  / (r.width/2);
  const my = (e.clientY - (r.top  + r.height/2)) / (r.height/2);
  try_ =  my * -5;   // invert Y: cursor above ⇒ top tips away
  trx =  mx * 6;
});

function frame(){
  rx += (trx - rx) * .09;
  ry += (try_ - ry) * .09;
  card.style.transform =
    `rotateY(${rx}deg) rotateX(${ry}deg) translate3d(${rx*1.6}px,${ry*1.2}px,0)`;
}
// the small translate is what sells it — pure rotation feels hinged, not floating

DEP-03

Focus falloff carousel

new — depth via blur, not position
What it does

Pointer position drives a virtual focal plane. Cards near it are sharp, full-opacity and forward; cards away from it blur and recede — a lens behaviour, not a layout behaviour.

When to use it

Product ranges where one item should dominate without a click. Depth-of-field is the cue the eye trusts most for distance, and it's cheaper than parallax because nothing needs to move far.

Code
const cards = [...stage.querySelectorAll('.card')];
let focus = 1, target = 1;                        // which card is "in focus"

stage.addEventListener('pointermove', e => {
  const r = stage.getBoundingClientRect();
  target = ((e.clientX - r.left) / r.width) * (cards.length - 1);
});

function frame(){
  focus += (target - focus) * .08;
  cards.forEach((c, i) => {
    const d = Math.abs(i - focus);                // distance from focal plane
    c.style.transform =
      `translateX(${(i - focus) * 62}%) scale(${1 - d * .12}) translateZ(0)`;
    c.style.filter  = `blur(${d * 5}px) brightness(${1 - d * .3})`;
    c.style.opacity = String(1 - d * .34);
    c.style.zIndex  = String(100 - Math.round(d * 10));
  });
}
// blur + brightness + scale together; any one alone reads flat

REA-01

Ember field with pointer wake

from veldara Particles, rewritten
What it does

Canvas particles rise with per-particle drift and flicker. The pointer applies a falloff repulsion, so sweeping through leaves a wake that settles — the page registers that you were there.

When to use it

Ambient life behind a hero. Scale count to viewport area, cap it, and never run it off screen. Additive blending is what makes embers glow instead of looking like dots.

Code
const P = [], N = Math.min(140, Math.floor(w * h / 9000));   // area-scaled, capped
for (let i = 0; i < N; i++) P.push({
  x: Math.random()*w, y: Math.random()*h,
  vx: (Math.random()-.5)*.25, vy: -(.18 + Math.random()*.55), // embers rise
  r: Math.random()*1.7 + .5, life: Math.random(),
  hue: 22 + Math.random()*26                                  // ember → gold
});

function frame(){
  ctx.clearRect(0,0,w,h);
  ctx.globalCompositeOperation = 'lighter';        // additive = glow
  for (const p of P){
    p.x += p.vx; p.y += p.vy;
    p.vx += (Math.random()-.5) * .02;              // thermal wander

    if (pointer.inside){                             // pointer wake
      const dx = p.x - pointer.x, dy = p.y - pointer.y;
      const d2 = dx*dx + dy*dy;
      if (d2 < 120*120){
        const f = (1 - Math.sqrt(d2)/120) * .9;    // linear falloff
        p.vx += (dx/(Math.sqrt(d2)||1)) * f;
        p.vy += (dy/(Math.sqrt(d2)||1)) * f;
      }
    }
    p.vx *= .97; p.vy = p.vy * .97 - .006;         // drag + buoyancy
    if (p.y < -10){ p.y = h + 10; p.x = Math.random()*w; }

    p.life += .015;
    const a = (.35 + Math.sin(p.life)*.3) * .8;    // flicker
    ctx.fillStyle = `hsla(${p.hue},85%,58%,${a})`;
    ctx.beginPath(); ctx.arc(p.x,p.y,p.r,0,6.283); ctx.fill();
  }
  ctx.globalCompositeOperation = 'source-over';
}

Move fast · then approach the button

REA-02

Spark trail + magnetic control

from Mouse_Trail_CTA, sparks not thumbnails
What it does

Two behaviours that belong together. Pointer velocity spawns sparks that fade and fall; the button reads pointer distance and leans toward it inside a radius, so it feels attracted rather than static.

When to use it

The trail is for one signature region, never page-wide. Magnetism belongs on the single most important control — used twice it stops meaning "this one matters." Cap displacement so the hit area never escapes the cursor.

Code
// ── spark trail: spawn on VELOCITY, not on every move event ──
let last = {x:0,y:0}, sparks = [];
stage.addEventListener('pointermove', e => {
  const r = stage.getBoundingClientRect();
  const x = e.clientX - r.left, y = e.clientY - r.top;
  const speed = Math.hypot(x - last.x, y - last.y);
  if (speed > 4){                                // slow moves stay quiet
    for (let i = 0; i < Math.min(3, speed/6); i++)
      sparks.push({ x, y, vx:(Math.random()-.5)*1.4,
                    vy:-Math.random()*1.1, life:1, r:Math.random()*1.6+.6 });
  }
  last = {x,y};
});

// in the shared loop: integrate, decay, cull
sparks = sparks.filter(s => {
  s.x += s.vx; s.y += s.vy; s.vy += .035;        // gravity: sparks arc and fall
  s.life -= .022;
  ctx.fillStyle = `rgba(233,150,60,${Math.max(0,s.life)})`;
  ctx.beginPath(); ctx.arc(s.x,s.y,s.r*s.life,0,6.283); ctx.fill();
  return s.life > 0;                                // filter IS the cleanup
});

// ── magnetic button ──
const r = btn.getBoundingClientRect();
const dx = px - (r.left + r.width/2), dy = py - (r.top + r.height/2);
const dist = Math.hypot(dx,dy), R = 150;
const pull = dist < R ? (1 - dist/R) : 0;
btn.style.transform = `translate(${dx*pull*.28}px, ${dy*pull*.28}px)`;
// .28 keeps the button under the cursor it's chasing — higher and it dodges you

COP-01

Character blur-stagger

from Cortex TextEffect
What it does

Splits a headline to characters and animates each from blur + brightness 0 + y-offset on a small stagger. Letters resolve out of heat haze rather than sliding in.

When to use it

Once per page, on the line that matters. Keep the stagger at 0.015s — 0.05 reads as a novelty typewriter. Always set aria-label on the parent, because split text destroys the accessible string.

Code
function splitChars(el){
  const text = el.textContent;
  el.setAttribute('aria-label', text);            // a11y: restore the string
  el.textContent = '';
  return [...text].map(c => {
    const s = document.createElement('span');
    s.className = 'ch'; s.textContent = c === ' ' ? ' ' : c;
    s.setAttribute('aria-hidden','true');
    s.style.cssText =
      'opacity:0;filter:blur(10px) brightness(0);transform:translateY(20px)';
    el.appendChild(s); return s;
  });
}

function reveal(chars, show){
  chars.forEach((c,i) => {
    c.style.transition = 'opacity .4s cubic-bezier(.16,1,.3,1),' +
                         'filter .4s cubic-bezier(.16,1,.3,1),' +
                         'transform .4s cubic-bezier(.16,1,.3,1)';
    c.style.transitionDelay = (i * 0.015) + 's';
    c.style.opacity   = show ? '1' : '0';
    c.style.filter    = show ? 'blur(0) brightness(1)' : 'blur(10px) brightness(0)';
    c.style.transform = show ? 'translateY(0)' : 'translateY(20px)';
  });
}
// drive with IntersectionObserver; CSS transitions, not rAF — the GPU handles it

COP-02

Velocity skew & settle

new — the "flows with purpose" mechanism
What it does

Measures scroll velocity, not position. Each line chases that velocity at its own rate, so lines lag apart into a whip and snap back together — skew, vertical drag, stretch and blur all scale with speed. The readout shows the live numbers.

When to use it

This is what makes a page feel physical rather than animated, and it's nearly free. The trick isn't the skew — it's the per-line rate difference. Move every line identically and you get a tilted block; stagger the rates and the type has mass.

Code
// ⚠ THE BUG WORTH KNOWING: don't lerp toward an already-decaying value.
// Double-damping cost ~80% of the amplitude and made this invisible.

let raw = 0, lastY = scrollY;
addEventListener('scroll', () => {
  raw += scrollY - lastY;                       // ACCUMULATE, don't overwrite
  lastY = scrollY;                              // sustained scroll builds up
}, { passive:true });

const lines = [...el.querySelectorAll('.vline')];
const RATES = [0.22, 0.15, 0.10];                 // ← the whole effect lives here
let smoothed = [0, 0, 0];

function frame(){
  raw *= 0.90;                                  // single decay, applied once
  raw = Math.max(-130, Math.min(130, raw));     // clamp the input, not the output

  lines.forEach((ln, i) => {
    smoothed[i] = lerp(smoothed[i], raw, RATES[i]);   // each line has inertia
    const v = smoothed[i];

    const skew  = Math.max(-14, Math.min(14, v * -0.11));
    const drag  = v * 0.34;                       // vertical lag — most visible part
    const sy    = 1 + Math.abs(v) * .0030;
    const blur  = Math.min(5, Math.abs(v) * .05);

    ln.style.transform = `translateY(${drag}px) skewY(${skew}deg) scaleY(${sy})`;
    ln.style.filter    = `blur(${blur}px)`;
  });
}

COP-03

Sticky set swap, opposing drift

from Deep Neural sol-sets
What it does

Stacked sets share one scroll range. Each fades and unblurs across four stops while its top half drifts up and bottom half drifts down — so every set opens and closes like a shutter.

When to use it

Sequential narrative in fixed vertical space — exactly the Spark → Wildfire → Afterglow arc. Opposing drift is the whole trick; move both halves the same way and it's just a slide.

Code
// piecewise interpolation across multi-stop ranges (Framer useTransform, vanilla)
function mapStops(v, inS, outS){
  if (v <= inS[0]) return outS[0];
  if (v >= inS[inS.length-1]) return outS[outS.length-1];
  for (let i = 0; i < inS.length-1; i++){
    if (v >= inS[i] && v <= inS[i+1]){
      const t = (v - inS[i]) / (inS[i+1] - inS[i]);
      return outS[i] + (outS[i+1] - outS[i]) * t;
    }
  }
}

const WINDOWS = [                       // four stops: in, hold, hold, out
  [0.00, 0.06, 0.26, 0.33],
  [0.34, 0.40, 0.60, 0.67],
  [0.68, 0.74, 0.94, 1.00],
];

sets.forEach((set, i) => {
  const w = WINDOWS[i];
  set.style.opacity = mapStops(p, w, [0,1,1,0]);
  set.style.filter  = `blur(${mapStops(p, w, [15,0,0,15])}px)`;
  const drift = mapStops(p, [w[0], w[3]], [0, 120]);
  set.querySelector('.t').style.transform = `translateY(${-drift}px)`;  // up
  set.querySelector('.b').style.transform = `translateY(${ drift}px)`;  // down
});

REV-01

Gradient mask wipe

from veldara card reveal
What it does

Rewrites mask-image each frame as a moving gradient edge, so content is uncovered rather than faded. The soft band is the reveal's whole character.

When to use it

Multi-column content that should feel written in, not popped in. Switch the axis to to bottom under 768px — a horizontal wipe on a single mobile column reveals nothing. Always will-change: mask-image.

Code
// progress 0→1 from a scroll trigger; rewrite the mask every frame
const axis = innerWidth < 768 ? 'to bottom' : 'to right';
const soft = innerWidth < 768 ? 20 : 15;         // edge softness, %
const lead = p * 130;                            // 130 > 100 so it fully clears

const mask = `linear-gradient(${axis},` +
             `black ${lead}%, transparent ${lead + soft}%)`;
grid.style.maskImage = mask;
grid.style.webkitMaskImage = mask;               // Safari still wants the prefix
// CSS: .grid { will-change: mask-image } — without it Safari repaints the world

REV-02

Aperture open

from Deep Neural clip-path reveal
What it does

Animates clip-path: inset() from 50% to 0 on an eased curve, so a full scene opens from a slit at centre. Reads as a shutter, or a roaster door.

When to use it

Section transitions where the next scene should feel revealed rather than scrolled to. Because it clips a container, everything inside — parallax planes and all — arrives together as one world.

Code
// cubic-bezier(.65,0,.35,1) solved by Newton-Raphson — worth it for the ease
function bezier(t,p1x,p1y,p2x,p2y){
  const cx=t=>((1-3*p2x+3*p1x)*t+(3*p2x-6*p1x))*t*t+3*p1x*t;
  const cy=t=>((1-3*p2y+3*p1y)*t+(3*p2y-6*p1y))*t*t+3*p1y*t;
  const dx=t=>(3*(1-3*p2x+3*p1x)*t+2*(3*p2x-6*p1x))*t+3*p1x;
  let g=t; for(let i=0;i<8;i++){const x=cx(g)-t,d=dx(g);
    if(Math.abs(x)<1e-6||Math.abs(d)<1e-6)break; g-=x/d;}
  return cy(g);
}

const eased = bezier(Math.min(1, p / 0.35), .65, 0, .35, 1);
const inset = 50 * (1 - eased);
wrap.style.clipPath = `inset(${inset}% ${inset}% round 3px)`;
// round 3px keeps the opening edge from looking laser-cut

REV-03

The Ratio — cream flood

new — their own ordering system
What it does

Their real menu lets you order Moon Milk by fraction. Picking one floods cream upward through a gradient mask and shifts the whole stage's colour temperature with it. No video, no images.

When to use it

This is the signature interaction — the screenshot-and-send moment. It works because the brand already named it: "find your sweet spot." Given buttons, it's keyboard-operable and announces state.

Code
let ratio = .25, shown = .25;

function frame(){
  shown += (ratio - shown) * .08;                 // cream pours, never snaps

  const top = 100 - shown * 100;                  // fill height from bottom
  const mask = `linear-gradient(to top,` +
               `black ${100-top}%, transparent ${100-top+14}%)`;
  milk.style.maskImage = mask;
  milk.style.webkitMaskImage = mask;

  // temperature travels with sweetness: ember at ⅛ → moonlight at ¾
  stage.style.background =
    `hsl(${24 + shown*26}, ${38 - shown*20}%, ${7 + shown*9}%)`;
}

buttons.forEach(b => b.addEventListener('click', () => {
  ratio = +b.dataset.r;
  buttons.forEach(o => o.setAttribute('aria-pressed', String(o === b)));
}));

How to use this. Each bench is independent — lift the snippet, keep the constants, swap the palette tokens. The constants marked in gold are the ones that were tuned by feel; they're the difference between the effect working and the effect being visible.

The architecture that matters more than any single effect: one requestAnimationFrame loop drives all fourteen demos, and each stage is registered with an IntersectionObserver so nothing off screen computes a thing. Fourteen private loops would idle this page at 100% CPU. That pattern is the actual takeaway.

What's still missing: real photography. Every plate here is procedural — layered gradients standing in for the roaster, the coals, the brick. Drop real plates into DEP-01 and DEP-03 and the depth stops being a demonstration and starts being a place.
